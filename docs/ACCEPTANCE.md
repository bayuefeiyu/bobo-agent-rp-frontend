# 设计场景与验收

## 本仓库基础自检

npm run verify 检查公开依赖哈希、接口目录一致性、场景覆盖、开发服务器边界、SDK/模拟器接通、代理隔离与构建产物。它不等于产品验收，也不代表真实 Pi/模型/生图已经测试。

fixtures/scenarios.mjs 是完全合成的设计输入。state 满足公开 State schema；其他 design 数据是说明用户处境的**非 API 视图模型**，不可直接当后端 DTO。真实 DTO 的例子必须标注 operation ID、版本、来源环境和脱敏方式，再经维护者确认。

模拟模式 POST /__dev/scenario，JSON {"id":"busy"} 可切换场景；GET /__dev/scenarios 可读列表。这些是开发控制接口，不是生产契约，真实代理模式不存在。POST /__dev/fault {"kind":"drop-after-input"} 可让下一次有效 input 在提交后断开响应，用于验证“未知结果不等于失败”。

模拟器仅支持 connection、card、state、opening、input、正文 revision 写入；launcher 仅支持 connection/cards。实际能力由 connection 返回。其他操作返回 501；没有模拟完整工作流、管理配置或候选采用。扩展模拟器时先补充经过确认的 DTO，不增加虚假能力。

## 必须覆盖的产品验收

| 场景 | 通过条件 |
| --- | --- |
| 启动器 | 可用/不可用卡可辨认；最近游玩；启动中防重复；失败可诊断；Pi 版本差异不阻断；正确接入返回的单卡服务 |
| 开场和聊天 | 浏览不创建会话；选择开场→首正文；恢复已有聊天；重载没有重复首正文 |
| 输入和阅读 | 输入→等待→正文；忙碌/阻断/失败状态准确；断线/重连/重载不重复提交 |
| 编辑与删除 | revision 冲突保留草稿；显示历史；删除前显示完整影响范围；取消不产生写入 |
| 候选 | 生成→比较→预览→采用；关联模块/图像随投影；两个客户端独立预览；预览禁普通输入 |
| 玩家偏好 | 资料 CRUD、至少一个资料、当前名字锁定、头像/字号；隐藏模块不改变权限 |
| 模块 | 分页绑定上下文；声明字段写入；稳定 operationId；未知结果查询回执；可选 renderer 不支持时降级 |
| 配置 | profile 全生命周期、导入导出、模型发现/测试/密钥处理；错误保留草稿；运行实例不被默认值变更追溯修改 |
| 监控 | 当前执行与历史区分；阻断/失败原因；允许的取消/跳过/重试/恢复；不可用动作明确解释 |
| 调用与费用 | 请求/响应/工具/团队记录；历史选择稳定；缺失记录和不完整用量可辨认 |
| 图像 | 资源加载失败可恢复；再生成和恢复按权限；切换预览不串图；对象 URL 释放 |
| 资料库 | 明确动作才构建/测试；刷新无写入；任务状态/取消/恢复；历史检索配置独立 |
| 扩展 | 合成自定义插件挂载、导航、返回、卸载、重挂载、故障回退；官方入口始终可达 |
| 可访问性 | 键盘完成主要任务；焦点和错误可理解；桌面/手机不丢功能；长文本和减少动画选项 |

每行需要真实后端证据或明确的待后端项。不能用设计稿、模拟成功或单元测试代替完整产品验收。实际模型调用和外部资源生成使用专用测试配置，由维护者协调。
