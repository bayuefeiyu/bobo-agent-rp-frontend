# 交给前端设计与开发 Agent

你将接手 AI 角色扮演项目的整个官方前端，负责产品体验、视觉设计、工程架构与重新实现。成果用于替换官方前端；不是只开发游玩插件，也不是旧页面换皮。

先阅读 AGENTS.md 和 README 的阅读顺序。所有必要输入应来自本仓库及明确提供的测试 API。不要查找旧前端源码、页面、截图、原项目 Git 历史或相邻工作区。不要复刻旧页面；从用户目标和业务行为重新设计。

本次包括启动器、游玩、玩家身份、模块、模型/Agent/profile 配置、工作流配置与监控、调用/Token、图像和创作资料库等全部界面。管理功能也由你实现，不能跳回旧官方界面。F01–F14 是验收范围，不是预设页面树。

你可以选择框架、设计系统、信息架构、布局与阅读形式。src 的连接诊断页不是产品设计；fixtures 的设计数据不是完整 API。不要把接口名称直接变成菜单，也不要虚构缺失的接口。

第一阶段先完成需求审计：用户任务、功能覆盖、关键状态、接口缺口、工程限制。提出两个有实质交互差异的整体方案，说明取舍并推荐一个。等待用户确认整体方向，再全面开发。没有必要在此之前确定全部视觉细节。

方向确认后持续完成可操作原型、真实 API 接入、异常处理、生命周期与验收。遗漏、延期或改变功能要明确列出并确认。明确区分模拟完成、真实联调通过和待后端支持。

保留产品扩展边界：创作者可以替换整个游玩区域，同时使用你新实现的官方管理和恢复能力。更深定制走官方 main 的派生分支。新应用应实现公开插件宿主，不必将整个官方应用做成一个 custom 前端包。

后端拥有业务规则、权威状态、权限、模型与工作流执行及持久化；只通过公开 SDK/API 接入。不复制后端业务规则、不访问运行时文件。契约不足时提出具体请求/响应和失败语义建议，由维护者协调，不擅自改固定 SDK。

必须处理上下文隔离、迟到响应、候选预览/采用、revision 冲突、草稿、未知提交结果、权限降级、断线重连和资源清理。快照轮询不是可靠事件流。旧卡不兼容；Pi 版本差异仅提示，不得仅因此阻断。

最终交付源代码、锁文件、可重复构建的静态产物、设计说明、功能覆盖、真实/模拟测试记录、后端接口缺口、生产集成说明和创作者宿主验收。执行 npm run verify，并依据 docs/ACCEPTANCE.md 完成产品级检查。工程自检通过不等于产品功能完成。
